# SFX brief: ability-feedback clips (batch E, 2026-11-07)

Scope: the six clip slots added to `AudioRegistrySO` in commit `0d123d97` (header "Ability feedback"): `HitConfirm`,
`CastWhiff`, `DeniedClick`, `ShellClose`, `ShellOpen`, `HuntLive`. They close the audio half of FEEDBACK.md §7.1
(cases 9, 10, 16, 29) and the Egg Shell "shell clack" hook from spec §4.7. The code hooks are already in; this brief
covers the clips only. No audio was made in this pass.

Tone: a kids' game. Toy-box, farmyard and cartoon sounds: wood, eggshell, felt, little whistles. Nothing harsh,
gory or scary. Even the "nothing happened" sounds should be friendly (a shrug, not a buzzer).

## Delivery

- **Format:** WAV, 48 kHz, 16-bit, mono. This is the convention `Assets/_Game/Audio/UI/MANIFEST.md` and
  `Assets/_Game/Audio/Abilities/MANIFEST.md` already use.
- **Mastering:** peak at or below -3 dBFS. Match each clip's loudest 100 ms (K-weighted) to about -15 LUFS, as for the
  shipped SFX. Add a 1 ms fade-in and an 8 ms fade-out, and make sure the first and last samples are zero. Integrated
  LUFS is not meaningful on clips shorter than 400 ms, so measure the loudest 100 ms with `Source~/analyse.py`.
- **Exception:** `DeniedClick` should be mastered quieter, at about -21 LUFS. The code plays it at volume 1.0 (see
  its row below), so the mastering is the only place to turn it down. This number is my recommendation, not taken
  from the code.
- **Files and slots:** put the files in `Assets/_Game/Audio/Abilities/` and drag each one into its slot on
  `Assets/_Game/Data/AudioRegistry.asset`. Then add a row for each to `Assets/_Game/Audio/Abilities/MANIFEST.md`.

| File | `AudioRegistrySO` slot |
|---|---|
| `hit_confirm.wav` | `HitConfirm` |
| `cast_whiff.wav` | `CastWhiff` |
| `denied_click.wav` | `DeniedClick` |
| `shell_close.wav` | `ShellClose` |
| `shell_open.wav` | `ShellOpen` |
| `hunt_live.wav` | `HuntLive` |

- **Empty slots stay silent.** `ProceduralAudioBank.FillMissing` does not synthesise these six slots. Until a clip
  is filled, `AudioRegistrySO.TryPlay` returns false, which is a legal no-op. The one exception is `HuntLive`: while
  it is empty, `MarkFeedback.PlayStings` falls back to `MarkLock` (currently `UI/equip_thunk.wav`) at volume 0.9,
  pitch 1.35. That fallback stops running once `HuntLive` is filled, and `HuntLive` then plays at **pitch 1.0**. So
  author the clip at the pitch it should actually sound.

## Playback path and loudness reference

- **No AudioMixer exists in the project.** There are no `.mixer` assets and no `AudioMixer` references in the
  scripts. Every SFX goes through `UnityAudioService.PlaySFX`, onto one 2D `AudioSource` (`_sfxSource`, with
  `PlayOneShot`) or onto one of six pitched voices. The final gain is
  `Clamp01(call volume) x master x PlayerPreferences.SfxVolume`. All six clips therefore go to the
  **SFX bus (no sub-group exists yet)**. A future SFX → Ability / SFX → UI split is a proposal only.
- **Spatial blend 0 (2D) for all of them.** That includes the Egg Shell clips, which come from a point in the world.
  There is no distance attenuation, so a shell far across the arena sounds as loud as one beside you.
- **No pitch variation.** `TryPlay` always plays at pitch 1.0, and there is one variant per slot. Design each clip so
  that hearing it again and again does not tire the ear.
- **The 0 dB reference is `AbilityActivate`, played at call volume 1.0** (`AbilityController`, `PlaySFX` with its
  default volume). Caveat: that slot is empty in the asset. At runtime it is the procedural saw sweep (360 to 920 Hz,
  180 ms, peak about 0.34). It is not mastered to -15 LUFS, so the dB figures below are call-gain ratios between
  clips mastered to the same convention. They are only exact once the cast cue itself is mastered.
- **Existing cues for comparison:** `AbilityFizzle` 0.55 (-5.2 dB), `AbilityCancel` 0.5 (-6.0 dB),
  `WhiffSfxVolumeMultiplier` 0.6 (-4.4 dB), `MarkKillLiveAssassinVolume` 0.9 (-0.9 dB).

## Per clip

### HitConfirm: 90 ms
- **When and who:** the local player's own cast lands on at least one rival (`LastCastHitCount > 0`). Only the
  caster's own peer hears it: it needs `HasInputAuthority`, and bots are excluded.
  Hook: `HitFeedback.ObserveOwnCast` calls `PlayCasterSfx`.
- **Character:** a short rising "tick-tink", like a wooden block tapped and then a small bell, pitched up about a
  fourth. Keep the body in the 1.5 to 3 kHz range, above where the cast sweep ends (920 Hz), because it will often
  sound on top of `AbilityActivate` from the same cast. Very fast attack, no tail. Reference: the "got it" tick in
  arcade pinball, but softer.
- **Loudness:** call volume 1.0, so 0 dB relative to `AbilityActivate`. If the two stacked together sound too
  loud, I suggest mastering this clip about 3 dB under the convention (a guess).
- **Accessibility:** the confirm ring and the caster micro-punch carry the same message on screen, so the cue reads
  with sound off. Under Reduced Motion the cue still plays (sound is not motion), and none of these hooks check
  Reduced Motion.

### CastWhiff: 120 ms
- **When and who:** the local player's own cast hits nobody, on the caster's peer only. Same hook and same gate as
  HitConfirm (the `else` branch of `ObserveOwnCast`).
- **Character:** a muted, downward-moving swish of air. Use soft band-passed noise from about 1.2 kHz down to
  500 Hz (the band is a guess), as if a feather duster swung at nothing. It must not sound like `AbilityFizzle` (the
  bright 2.6 to 0.9 kHz "pfft" that plays when a move is released with nobody in range) or like `Swing`.
- **Loudness:** `FeedbackTuning.WhiffSfxVolumeMultiplier` = 0.6, which is **-4.4 dB** relative to `AbilityActivate`.
  Master it to the normal convention; the code does the turning down.
- **Accessibility:** the grey, dimmed whiff ring (`WhiffRingAlphaMultiplier` 0.55) is its visual twin. On a Steal
  whiff, `PlayStealWhiff` also runs.

### DeniedClick: 40 ms
- **When and who:** one click per consumed refused press, together with the hex bump. Only the local HUD plays it.
  Hook: `TouchControlsController.PollDeniedPress` (which consumes `AbilityController.TryConsumeDeniedPress`) calls
  `PlayDeniedClick`.
- **Character:** a dry, muted "thock", like a felt-tipped mallet on a closed wooden box. It falls slightly in pitch
  and has no ring. It must not sound like `AbilityCancel` (the soft 240 Hz sine tick), so sit it around 600 to
  900 Hz (a guess). It means "not now", never "error".
- **Loudness:** the call volume is 1.0, because `TryPlay` uses its default volume. So master it about **-6 dB**
  (around -21 LUFS) to land level with the cancel tick. This value is a recommendation. A `DeniedClickSfxVolume`
  constant in `FeedbackTuning` would be the cleaner fix, which is senior-dev's call.
- **Accessibility:** the hex bump (and its red-X or refusal state) is the main cue. The sound only backs it up.

### ShellClose: 120 ms
- **When and who:** the Egg Shell close edge. Every peer that sees the egg hears it.
  Hook: `ChickenShellVisuals.EnterClose` calls `PlayEdgeSfx(open: false)`. It is reached only from the edge switch in
  `Observe`, never from the seeding pass, so a player who joins late does not hear it.
- **Character:** a hollow wooden "clack": two halves of a toy egg snapping shut. One bright transient, then a short
  low knock (around 200 to 400 Hz, a guess). The 0.12 s squash and the 6 dust puffs land on it.
- **Loudness:** call volume 1.0, so 0 dB relative to `AbilityActivate`.
- **Accessibility:** the caster also gets the 15 ms `HapticRules.CancelArm` tick (amplitude 80) on their own phone.
  That needs `HasInputAuthority`, and it never fires for bots or decoys. The EGG! pop and the closed egg are the
  visual twins. The clip is silent while the bird is faded or `HiddenVisibilityRules.IsHiddenFor` holds, so Hide
  never leaks a position through sound.

### ShellOpen: 200 ms
- **When and who:** the hatch edge. It fires on timeout, on a second press, and on another cast, and every peer that
  sees the egg hears it.
  Hook: `ChickenShellVisuals.EnterOpen` calls `PlayEdgeSfx(open: true)`.
- **Character:** a two-note "crack-pop". First an eggshell crack (a crisp, crunchy transient), then a rising cork
  "pop" about a fifth higher, landing on the cap tumble and the shard and feather burst. Cheerful, like something
  being born, not something breaking.
- **Loudness:** call volume 1.0, so 0 dB relative to `AbilityActivate`.
- **Accessibility:** the visual twins are the HATCH! pop and the shards. The fade/Hide silence gate is the same as
  ShellClose's. There is no haptic on open.

### HuntLive: 250 ms
- **When and who:** the Death Mark kill goes live (the HUNT! pop). Only the Assassin's (hunter's) peer hears it.
  Hook: `MarkFeedback.PlayStings`, the `KillLive` branch for `MarkRole.Assassin`. The victim's peer hears
  `MarkVictim` (1.0, pitch 1.15) and observers hear `MarkLock` (0.45, pitch 1.35). **HuntLive is never played on the
  victim's peer.**
- **Character:** a short, bright "go!" sting: a whistle or slide whistle rising into a single banjo pluck or marimba
  hit. It should feel like "pounce!", not like a threat. It must not resemble the `MarkVictim` sting, so keep it
  rising (the victim hears warning cues).
- **Loudness:** `FeedbackTuning.MarkKillLiveAssassinVolume` = 0.9, which is **-0.9 dB** relative to
  `AbilityActivate`, at pitch 1.0.
- **Accessibility:** the HUNT! pop is the visual twin. When this slot is empty, the pitched-up `MarkLock` keeps the
  moment audible (see Delivery).
